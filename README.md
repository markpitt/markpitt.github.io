The source of my personal profile site, markpitt.dev. Built with Astro and Tailwind CSS, deployed to GitHub Pages.

## Setup

You need Node.js 22.12 or later.

```sh
npm install
npm run dev
```

## Commands

All commands are run from the root of the project, from a terminal:

| Command           | Action                                |
| :---------------- | :------------------------------------ |
| `npm run dev`     | Starts the local dev server           |
| `npm run build`   | Builds the production site to `dist/` |
| `npm run preview` | Previews the built site locally       |

## Project structure

```text
src/pages/        Routes, including the homepage
src/components/   Section components: About, Contact, Experience, Expertise, Hero, Nav, Work
src/layouts/      Base.astro, the root page layout
src/styles/       Tailwind entry point (global.css)
public/           Static assets copied verbatim to dist/
```

## Deployment

`.github/workflows/pages.yml` builds the site on every pull request and, on a push to `main`,
deploys `dist/` to GitHub Pages. No secrets are needed: the deploy job asks for `pages: write` and
`id-token: write` itself.

This is the `markpitt.github.io` user site, served at the root of the custom domain `markpitt.dev`.
The domain is set under **Settings > Pages > Custom domain** (an Actions deploy ignores a `CNAME`
file), with **Enforce HTTPS** on. DNS stays on Cloudflare, DNS only (no proxy), so GitHub can issue
the certificate: four A and four AAAA records on the root, and `www` as a CNAME to
`markpitt.github.io`.

## Build output

`npm run build` produces `dist/` for GitHub Pages, plus two generated artefacts that are not static files in `public/`:

- **`sitemap-index.xml`**, from the `@astrojs/sitemap` integration configured in `astro.config.mjs`.
- **`robots.txt`**, generated by `src/pages/robots.txt.ts` rather than a static file in `public/`. It is a build-time endpoint rather than a static asset, because the sitemap URL it names is derived from `site` rather than hardcoded. If the domain in `astro.config.mjs` ever changes, this file changes with it. Do not add a `public/robots.txt`: the two would conflict.

`Base.astro` derives one canonical URL constant from `Astro.url.pathname` and `Astro.site` and reuses it for `<link rel="canonical">`, the Open Graph `og:url` tag, and the JSON-LD `Person` block's `url` field, so the three cannot drift apart from each other.
